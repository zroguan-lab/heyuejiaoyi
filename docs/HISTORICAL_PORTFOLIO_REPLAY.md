# V2.3 历史交易与组合回放（RESEARCH-M4）

## 目标与权威边界

M4不重新实现策略。`historical-market-replay.js`继续负责逐时点产生与实时同源的V2.3决策；`historical-portfolio-replay.js`只负责订单生命周期和组合账。

```text
历史原始事实 -> M3逐时点雷达/V2.3决策
            -> M4订单状态机
            -> 交易流水、费用、Funding、权益曲线
```

策略候选、评分和拒绝原因的权威仍在V2.3策略引擎；历史成交状态、逐笔损益和组合权益的权威在M4回放结果。两层不能相互修改对方的事实。

## 当前成交模型

- 固定风险：每笔目标风险由当时账户权益乘以V2.3风险比例得到，不再固定10U保证金。
- 持仓数量：不设置人为笔数上限；只有同标的占用和真实可用权益不足会拒绝。
- V2.3主动限价IOC：用信号后第一根完整1分钟K线的开盘价检查最大不利滑点边界；通过后按信号价记账，并单列配置滑点成本；超限即取消，不算亏损。
- 被动限价GTC：按1分钟高低价触及判断成交，遵守信号过期时间。
- 出场：同根K线同时触发时按止损优先；TP1平50%，剩余仓位移动到保本，之后等待TP2或保本止损。
- 成本：入场/出场手续费、配置滑点和逐时点Funding独立记账。
- 组合账：500U起始权益，输出余额、按最近收盘价盯市权益、占用保证金、可用保证金、回撤和北京时间每日权益。
- 点时事实：M3加载的全市场覆盖快照原样传入每个M4决策时点，组合账不得把已通过的严格输入降级为“覆盖不完整”。

## 运行

严格点时模式，默认回放最近288个雷达刷新点：

```powershell
npm run replay:portfolio
```

缩短检查或输出完整逐笔审计：

```powershell
npm run replay:portfolio -- --points=24
npm run replay:portfolio -- --points=24 --full
```

只用于研究当前元数据对历史K线的影响：

```powershell
npm run replay:portfolio -- --research-only-current-metadata --points=24
```

## 晋级限制

当前结果固定为 `promotionEligible=false`。即使逐时点行情覆盖完整，历史盘口、队列位置和逐笔撮合仍不可得，IOC只能使用保守代理。该结果可以发现策略与账务问题，不能单独证明未来盈利能力。

完整晋级还需要：历史Top100全市场覆盖、逐时点点差或盘口、至少180天数据、走步验证、封存样本、参数稳定性和与Demo前向成交差异审计。
