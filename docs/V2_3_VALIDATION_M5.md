# V2.3 走步验证与封存样本（RESEARCH-M5）

## 目标

M5回答的不是“某段历史赚了多少钱”，而是：在不偷看未来、不反复打开最终样本的前提下，V2.3是否在多个样本外窗口保持正期望，并且数据质量是否足以支持结论。

权威边界：

- V2.3策略引擎拥有候选、方向、评分和拒绝原因；
- M3拥有逐时点雷达与历史输入；
- M4拥有成交、费用、Funding、逐笔损益和组合权益；
- M5只拥有样本切分、统计、封存状态和晋级判定，不得改写前面三层的事实。

## 默认验证协议

1. 时间顺序去重并严格升序；
2. 最后20%作为封存样本，默认不运行；
3. 前80%采用扩展训练窗和4个互不重叠的样本外验证窗；
4. 每个验证窗独立从500U开始，避免跨窗口状态污染；
5. 输出策略、方向和实验层级的分层结果；
6. 晋级至少要求：逐时点输入合格、100笔已平仓样本、PF不低于1.2、平均Net R大于0.10R、最差窗口回撤不高于10%、至少一半窗口盈利、单一币种利润占比低于20%、单一市场事件利润占比低于25%；
7. 报告必须拆分候选来源、PRE_BREAKOUT多空、爆发/方向评分区间和A/B层，不能只给组合总数。
8. 三组邻近参数中至少三分之二保持正期望，才算初步参数稳定；
9. 通过历史闸门不等于保证未来盈利，还必须与Binance Demo前向成交对照。

## 运行

当前目录使用事后合约快照、没有历史盘口，必须明确标记研究模式：

```powershell
npm run validate:v2.3 -- --research-only-current-metadata --points=288
```

同时检查阈值上下5分的参数稳定性：

```powershell
npm run validate:v2.3 -- --research-only-current-metadata --points=288 --stability
```

封存样本默认保持 `SEALED`。只有策略、参数和数据版本冻结后，才可以显式打开一次：

```powershell
npm run validate:v2.3 -- --open-holdout=OPEN_V2_3_SEALED_HOLDOUT --points=288
```

如果严格点时元数据不完整，打开操作仍会失败，不能通过切换标志绕过。

## 当前数据闸门

验证报告会明确列出：标的数、共同历史天数、历史点差标的数、合约快照数和全市场覆盖声明。晋级目标为至少100个当时合格标的、180天共同历史、逐时点点差或盘口、多个合约快照以及可审计的Top100覆盖声明。
