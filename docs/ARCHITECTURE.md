# 架构与安全边界

## 当前目标

当前代码规则基准（2026-10-17）：V2.4.3；正常成本组阈值为0.20R，高成本探索组上限为0.35R。V2.4.3在去除RETAINED后对BOUNDARY_PRESSURE-only候选仅研究、不执行，其余沿用V2.4.2规则。详见 `quant-team/STRATEGY_AUTHORITY.md` 与 `docs/GROK_BOT_V2_4_3_TRADING_LOGIC.md`。代码版本不代表某个既有服务进程已经加载新源码，运行结论须另附实时证据。

## Demo 与真实资金的组合风险边界

- Demo 研究模式的目标是收集无偏样本：组合相关性、同方向暴露和理论总风险只记录、分组和复盘，不作为第二道信号拒绝门槛。
- 真实资金模式必须新增独立 `Live Portfolio Risk Gate`：执行总风险、单方向风险、相关性集群、保证金占用、强平距离和账户回撤限制。
- 两种模式共用信号与风险测量，但执行政策必须分离；不得为了未来实盘而污染当前Demo样本，也不得把Demo的“不限样本数”直接继承到真实资金。
- 是否启用真实资金风控属于未来显式发布决策，不能由研究回放、模型评分或历史闸门自动开启。

## 核心不变量

- 未收盘 K 线不得进入策略。
- Binance 主源不可用时停止生成信号，不静默回退到辅助行情。
- 一个币种同一时间只能有一个活动策略执行；反向候选全部取消，同向候选合并归因。
- V2.4候选必须来自波动收缩、结构边界蓄势、早期量能抬升、排名加速、核心市场或最短观察期保留；雷达只负责找候选，不能单独触发订单。
- V2.4必须在价格尚未收盘突破结构边界时生成 `PRE_BREAKOUT`；已经突破的标的不得伪装成爆发前机会。
- V2.4 的 A 级核心层为 70 分及以上，B 级探索层为 55–69 分；达到任一层且未触发安全硬拒绝的不同标的信号才可继续检查Demo成本门控，不设置固定持仓笔数。
- V2.4必须拒绝预估总成本大于0.20R的新订单；该信号仍在V2.4反事实研究账本模拟完整生命周期。
- 普通趋势冲突、位置偏离、实体扩张和成本偏高只能扣分并形成质量观察，不得再作为第二次硬拒绝；数据缺失、仓位计划无效、极端追价和极端成本仍可硬拒绝。
- 相关性和本地组合风险只用于统计与复盘，不在 Demo 样本收集阶段截断不同标的信号。
- V1 全样本执行已经停用；其信号、订单和绩效只保留为历史，不能再次成为新订单来源。
- V2 必须写入独立 `shadow_signals`，不得修改 V1 `signals.selected`，记录永久携带 `orderSubmissionAllowed=false`；只有配置为 `V2_PRODUCTION` 的 Demo 适配器可在校验绩效纪元、入选状态和全部执行前置条件后提升信号，影子域本身仍不能调用交易所。
- 自动执行在任意时刻只能选择一个策略源；禁止 V1/V2 同时订阅和混合发单。
- 执行对账按轮次共享账户快照，K 线按收盘周期缓存；418/429 封禁窗口由同进程所有 Binance 客户端共享，持仓数量增加不会按仓位重复拉取整套账户数据。
- 模拟交易固定使用 10 USDT 逐仓保证金和 10 倍杠杆；该模型不等于真实账户可承受风险。
- 最终成交率低于计划量95%的新执行不得进入策略绩效：必须先建立保护，再受控平掉已成交部分，并保留完整执行审计。
- 所有结果以手续费、滑点和资金费率后的净值为主，同时保留毛值。
- NetR、MFE和MAE的风险分母使用实际成交价、实际成交数量与计划止损导出的实际风险，不得把未成交的计划数量纳入分母。
- TP1 平掉一半后，剩余仓位止损移动到入场价；同一最小路径内无法判断先后时按止损优先。
- 手动跟单使用用户填写的实际成交价和数量独立核算，不篡改模拟组合结果。
- 本地 HTTP API 不提供交易所下单、撤单或紧急停止路由；发单只能经过独立命令入口或显式启用的 Demo 自动协调器，并始终经过写入总锁和一次性确认码。
- 测试网账户状态以 Binance 为事实源，SQLite 只保存脱敏投影与审计快照；本地模拟组合不能覆盖交易所状态。
- 交易客户端仅接受精确 Demo/Testnet 域名和当前监控池 USDT 永续白名单；未显式解锁时，所有白名单写操作仍在本地拒绝。
- 未通过测试网、凭据、交易权限、连接、单向持仓和账户归属检查时，不得准备新订单；系统已认领且有活动止损的其他标的仓位可以继续运行，未知外部状态一律冻结新入场。
- 全系统允许任意数量不同标的的未结束测试网执行记录，但同一标的只能有一个；实际可用余额由每次下单前的账户校验和 Binance Demo 最终约束。每个信号只能创建一次，待确认计划过期后自动取消并释放预留。网络超时后必须按客户端订单号查询，禁止盲目重试。
- 每个入场、止损、止盈、保本止损和主动平仓订单都必须在提交前拥有一句话原因；原因、策略版本、评分和市场事件批次进入执行计划哈希，缺失原因时执行层拒绝下单。
- 自动协调器只接受当前策略源、当前绩效纪元内、`ENTRY_PENDING` 且剩余有效期不少于 30 秒的已选策略信号；人工金丝雀、V1历史、旧纪元、已止盈、已结束和已过期信号不得自动执行。
- 入场实际成交数量大于零后必须先确认全仓止损，再建立止盈；止损无法确认时自动阻止所有新入场。
- TP1 成交后必须先确认新的reduce-only数量型保本止损覆盖当前全部剩余仓位，再撤销原Close-All止损；保本止损创建失败时保留原止损并退避重试，禁止产生无保护窗口。
- `SUBMISSION_UNKNOWN`、`PROTECTION_INCOMPLETE` 或 `ERROR_UNPROTECTED` 任一活动执行存在时，自动协调器全局暂停新入场。
- 只允许撤销系统保存且可审计的订单 ID，禁止账户级全撤。

## 策略边界

1 小时方向必须由 EMA20/EMA50、均线斜率、价格位置和已确认结构共同支持。V2.3要求15分钟近期真实波幅相对基线收缩、价格靠近方向侧结构边界但尚未突破，再用5分钟量能抬升、净移动、连续收盘与K线实体压力计算方向可信度。预估成本、流动性和市场环境继续参与最终评分。

爆发概率与方向可信度必须分别记录，不能只保存一个总分；这样复盘时才能区分“没有爆发”和“方向判断错误”。

V2.3先在高流动性发现池计算已收盘15分钟K线上的收益、收缩比、量能抬升、边界距离、排名速度和相对强弱，再把最多30个候选交给Pre-Move引擎。引擎每5分钟只为尚未突破且爆发/方向评分都达到最低门槛的标的生成候选，并用受滑点预算约束的IOC限价执行。

V2.3研究账本仍计算0.5%权益风险对应的理论仓位，用于比较信号质量，但不以本地总风险预算、相关性或固定持仓数量筛掉样本。当前Demo执行统一使用目标10U保证金、10倍逐仓；余额、同标的唯一、单向持仓、保护单和交易所规则仍是强制安全边界。

## 验证边界

- 历史 K 线按时间分页、去重、排序，并排除未收盘数据。
- 回测只允许使用决策时点之前已收盘的 1h/15m/5m 数据，禁止未来函数。
- 交易生成之后才读取后续 1m 路径；没有 1m 时降级为 5m 且按止损优先。
- 使用扩展窗口滚动样本外验证，最后 20% 数据保持封存，不参与调参。
- 每个走步窗口必须真实运行并输出交易结果；仅生成时间区间不算完成验证。邻近参数至少三组，并报告正期望比例和中位平均净R。
- V2.3初步验收要求运行不少于30天且至少100笔前向已结束交易，并独立报告候选来源、PRE_BREAKOUT-LONG、PRE_BREAKOUT-SHORT、爆发/方向评分区间以及A/B两层；扣除成本后平均净R需大于0.10R、Profit Factor不低于1.2、最大回撤低于10%，单一币种利润占比低于20%、单一市场事件低于25%。
- 报告组合、策略和多空方向结果，并同时展示成交、过期、未结束交易及全部成本。
- 标的池每次刷新保存完整快照，历史回测应按当时池成员运行，避免幸存者偏差。

## 故障恢复

实时进程恢复时，若交易路径缺口超过普通 500 根 1m K 线窗口，会使用历史分页补齐，再推进交易状态。研究候选、本地模拟挂单/持仓、手动跟单和标的池快照以 SQLite 为事实源；进程内状态只用于加速展示。测试网订单与持仓则以 Binance 为事实源，SQLite 中的账户快照仅用于缓存和审计，连接失败时必须明确标记为断开。

## M4 当前边界

- 使用 Binance 服务器时间计算签名时差；密钥只在进程内传给只读客户端，不进入配置 API、数据库或日志。
- 只读侧覆盖账户、全账户持仓、普通挂单、Algo 条件单、持仓模式和目标合约配置。
- 网页分别显示本地模拟组合与 Binance 测试网账户，避免把研究记录误认为交易所仓位。
- 执行侧使用触发信号自身的白名单标的，固定逐仓、10 倍杠杆、单笔约 10 USDT 保证金；不同标的活动执行不设固定数量或本地总预留上限。
- 合约数量和价格只使用 `PRICE_FILTER`、`LOT_SIZE`、`MIN_NOTIONAL`，不使用展示精度代替 tick/step。
- 条件止盈止损使用 Binance 当前 `/fapi/v1/algoOrder` 接口；止损使用 Close-All，TP1 使用 Reduce-Only，TP2 关闭剩余仓位。
- 部分成交立即撤销剩余入场；成交率达到95%及以上时按实际成交风险管理，若数量不足以安全拆成两份则降级为单一止盈；成交率低于95%时先建立保护、再受控平仓并排除绩效。
- TP1 成交后先用新的唯一 Algo ID 在入场价确认覆盖全部剩余数量的reduce-only保本止损，再撤销原Close-All止损；切换失败时原止损继续有效，重试使用退避。
- 紧急停止不是日内亏损熔断：它停止新入场、撤销系统自己的等待入场单，并持续处理随后才被查询到的未知提交，但不粗暴撤掉已有仓位保护；当所有现有仓位均可归属且有活动止损、没有未知提交时可以解除，不要求受保护仓位全部平仓。

## 进入真实资金前仍必须新增

Demo 策略闭环通过不代表可以直接扩大风险。至少还需要：

- 使用用户数据流降低 REST 轮询延迟，并验证长时间断线重连；
- 真实账户保证金、强平距离、全局敞口、相关性和极端行情保护；
- 密钥最小权限、IP 白名单、本机安全存储、日志脱敏与人工紧急停机；
- 足够长的前向测试网演练和可接受标准；
- 执行服务默认关闭，必须由明确配置和人工动作开启。

用户决定模拟阶段不设置日内熔断；这一选择只适用于不会产生真实损失的 Phase A。进入 Phase C 前，真实资金风险保护必须重新确认，不能继承“无熔断”假设。
