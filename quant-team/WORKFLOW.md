# 协作流程

## 接任务
总控记录任务ID、用户原意、授权范围、不可变项、事实源、时间边界、交付物、验收人。
本轮审查只读；无需“等用户再次确认”才能执行已授权检查。不能据此扩大到改策略或处理订单。
历史只读阶段为TEAM-001/002；TEAM-003按tasks/TEAM-003.md执行精确分工，允许被指定负责人在边界内实施统计修复、隔离测试和文档。纯统计修复不得影响策略及订单决策。

## 调度
侧边栏独立专家任务的threadId登记在REGISTRY.json的sidebarThread中。总控01a0de95-140b-78b0-befd-55af63f485a9是用户统一入口。TEAM-002每位专家只读初始化岗位/技能后回合结束、待命；不得通过sleep/轮询声称常驻。
总控向已注册专家发送具体任务，默认由总控读取结果并中转讨论；发送与读取使用真实threadId，不使用/root/worker名称冒充聊天ID。每个独立聊天默认保留用户的模型设置，本轮不指定新模型。
最多总控+3个子 Agent 并行。8个岗位可由执行实例分批担任，换岗时重新读取岗位和技能，记录实际实例ID与阶段。
不能伪装为8个永久在线专家，也不能让同实例对自己刚实现的工作独立验收。
独立检查先各自取证，再交换发现，避免把总控预设结论当正确答案。
专家可以在本任务内通过协作消息质疑其他专家；消息和回复需带任务ID及证据，不安排外部通信。

## 输出契约
- role/task/time/scope：岗位、任务、时间及允许范围。
- evidence：文件:行号、查询、版本、快照时间和分母；外部资料给直达来源。
- observations：FACT/INFERENCE/HYPOTHESIS/UNKNOWN。
- finding：严重程度、复现条件、影响、建议，区分现有问题和本轮引入问题。
- cross_review：对方观点、同意或异议、补证要求和回复。
- verdict：PASS / FAIL / BLOCKED / PARTIAL，说明该结论究竟验收了什么。
- limits：未运行、没权限、数据不足、动态状态漂移。
不得保存完整账户响应、原始凭据或未脱敏日志。

## 只读技术方法
查询SQLite使用 node:sqlite 的 DatabaseSync(path,{readOnly:true}) 及 SELECT；不要实例化 ResearchStore.initialize（会创建表/写元数据）。
线上只允许现有 GET /、GET /api/health、GET /api/signals；不得自动触发扫描、启动服务或发交易请求。记录 HTTP超时和嵌套字段路径，空字段不是零。
隔离纯函数检查不连接交易所、不加载 .env、不导入 src/index.js。本轮不运行可能写数据或连接服务的批处理。
读取历史仓库先核对目录含义，不打开封存/holdout数据。
只读连接仍不能保证活跃服务停止写入；数据库文件哈希变化不能直接归罪于审查 Agent。策略文件/配置前后哈希与命令记录用于检查本轮变更边界。

## 讨论与验收
分轮呈现：独立发现 -> 真实交叉质疑 -> 证据复核 -> 总控裁决。关键分歧未解决不得写“全部正常”。
首轮验收：版本识别、数据分账、执行边界、反事实过滤、小样本结论、工具失败如实披露、无策略/配置/订单改动。
后续开发：实现者交付后由其他实例复测；明确失败条件、回滚版本及残留风险。

## 记录
总控维护 TASKS.md 和 acceptance/ 的任务记录。专家阶段可以是 COMPLETE，但岗位总能力仍为 PARTIAL；当前模拟协作只证明覆盖到的场景。
